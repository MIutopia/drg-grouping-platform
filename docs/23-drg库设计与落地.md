## 二、设计要点

### 2.1 为什么单独做一个受控 DDL 层

`dbio.py` 刻意拒绝一切非 SELECT 语句（只读护栏）。建库属于例外，因此新增 `ddlio.py`，
把例外收得很窄：

1. **必须显式开启**：环境变量 `DRG_ALLOW_DDL=1`，否则直接 `PermissionError`；
2. **只执行版本库内的文件**：调用方只能传 `src/sql/` 下的文件名，不能传任意 SQL；
3. **语句白名单**：CREATE / ALTER TABLE / INSERT / DROP TABLE 等逐条限定；
4. **全程留痕**：每个脚本的文件名 + `sha256` + 批数 + 耗时写入 `drg.ops_ddl_log`，
   任何时候都能确认库里是哪一版脚本建的。

### 2.2 去标识化

`result_settlement_return` **不复制**官方返回中的 `patient_name` / `id_card` / `person_code`，
只保留住院号（`medical_no`）——它是全链路唯一需要的关联键。

### 2.3 结果表统一命名

`result_pnl` 把全院/病组/科室三层用 `level` 字段统一到一张表，便于 Metabase 直接取数。

## 三、建库过程中发现并修复的 6 个缺陷

这些都是**真实缺陷**，不是配置问题——记录下来供审计追溯。

| # | 缺陷 | 现象 | 修复 |
|---|---|---|---|
| 1 | `rule` 是保留字 | `03_result.sql` 建表报 `Incorrect syntax near 'rule'` | 列名加方括号 `[rule]` |
| 2 | 长文本进主键 | `finding nvarchar(1000)` 超主键 900 字节上限 | 改用 `IDENTITY` 代理主键 |
| 3 | **主诊表一码多 MDC** | 14 个诊断码同属 MDCM 与 MDCN（`C49.503 会阴结缔组织恶性肿瘤` 等会阴/生殖部位码，男性归 M、女性归 N），原主键 `(code, policy_version)` 拒绝第二行 | 主键改为 `(code, mdc, policy_version)` |
| 4 | **入组条件混入 997 行非 ADRG 数据** | `drg_cond.csv` 中 997 行的 `adrg` 列装的是**中文名称**（`头颈部创伤`/`泌尿系统创伤`/`生殖系统创伤`/`躯干、脊柱创伤` 等 9 组），长度 5–7 字符，落库时超 `varchar(8)` 截断 | 从 ADRG 条件中分离，独立为 **`dict_mdcz_dx`**（MDCZ 多发严重创伤诊断清单）；**剔除后引擎回测指标不变**（96.0%）→ 证明这 997 行原本就是死重 |
| 5 | 同表双 kind 互相清空 | `dict_no_main` 的 dx/op 分两次装载，第二次 DELETE 抹掉第一次（1,822 而非 3,671） | 合并成一个 DataFrame 再装 |
| 6 | pymssql 不接受 numpy 标量 | `ValueError: Unsupported parameter type: <class 'numpy.int64'>` | 在 `_clean` 中统一解包为 Python 内建类型 |

### 3.1 顺带查清的一件事：MDCZ 的主诊表是缺失的

- `主诊表`（sheet）中 **MDCZ 行数为 0**；
- 而 `入组条件` 中 MDCZ 有 **6,045 行**，其中 997 行是上述"名称当码"的诊断清单；
- 这 997 个诊断码**全部同时属于其他 MDC**（如 `S01.800x011` 属 MDCB）。

**含义**：MDCZ（多发严重创伤）是一条**跨 MDC 的优先级规则**，不是普通 ADRG 入组条件；
其判定还需临床严重度条件（如 ISS 评分），**目前尚未接入引擎**。
本次把它完整保留为 `dict_mdcz_dx`，不丢失、也不误用。

## 四、可重复性

```powershell
$env:DRG_SBO_PASSWORD = "***"; $env:DRG_ALLOW_DDL = "1"; $env:PYTHONIOENCODING = "utf-8"

python src\etl\s18_create_drg_db.py --check     # 权限/环境/数据齐备性体检（只读）
python src\etl\s18_create_drg_db.py --create    # 建库建表（幂等）
python src\etl\s18_create_drg_db.py --load      # 装载字典/参数/结果（幂等）
python src\etl\s18_create_drg_db.py --verify    # 从库内重算关键指标
python src\etl\s18_create_drg_db.py --status    # 各表行数
python src\etl\s18_create_drg_db.py --schema    # 源数据长度 vs 目标列宽核对
python src\etl\s18_create_drg_db.py --sql 05_fix_main_dx_pk.sql   # 执行单个迁移脚本
```

- 所有 DDL 脚本幂等（`IF OBJECT_ID(...) IS NULL`），重复执行安全；
- 所有装载"先清后插"，重复执行不会产生重复行；
- DDL 留痕含 `sha256`，可核对库里是哪一版。
