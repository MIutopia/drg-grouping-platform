## 三、`etl/dbio.py` —— 源库只读访问层（共用基础件）

**职责**：提供唯一的数据访问入口，所有作业共用。

> **源库表名走配置（2026-09-27 起）**：作业代码里不写物理表名，只写自解释令牌
> `源表(key)`（如 `源表(admission)`、`源表(fee_cure_in)`）；物理表名集中在
> `src/config/source_schema.json`，由 `dbio` 在执行前展开——**全项目唯一的展开点**。
> 换现场或换 HIS 版本只改配置，不动任何 SQL 文本；缺键会明确报错，不会静默拼出空表名。
> **列名同样走配置（2026-09-28 起）**：SQL 里写 `列(key)`（如 `列(hospital_no)`），pandas 侧用
> `src_col(key)`；物理列名集中在 `src/config/source_columns.json`。
> **查询结果的列名仍是物理列名**，所以 CSV 产物与 drg 装载契约不变（这点刻意如此，否则会牵动
> 全部下游）。判据：只认"出现在 SQL 语句里、且不作赋值目标"的 token——`n_hit`/`列(off)` 等是我方
> 计数变量，按前缀取词会误改坏代码（首轮已踩，6 个文件语法错）。
> `s00_env_check` 第 5 节自检"代码里是否又写回了物理表名/列名"（含既有系统侧 `Drg_*` 与备份库表名）。

**设计原则**：
1. **只读** —— 只提供 `query_df` / `query_rows` / `scalar`，不提供任何写方法；另有 `_guard_readonly()` 对 SQL 首关键字做黑名单拦截（INSERT/UPDATE/DELETE/MERGE/DROP/ALTER/TRUNCATE/EXEC/CREATE/GRANT/REVOKE/BACKUP/RESTORE）；
2. **兼容 SQL Server 2014**（源库版本），SQL 不依赖 2016+ 语法；
3. **驱动双路**：优先 `pymssql`，失败回退 `pyodbc`(ODBC Driver 18)，便于在信息科不同环境落地；
4. **中文乱码自动还原**：源库 `varchar` 中文列在部分驱动下会按 latin-1 逐字节解码，产生 `Ï¥¹Ø½Ú²¡` 式乱码（实为 GBK 字节被映射）。`fix_mojibake()` 仅在「还原后中文字符明显增多」时才替换，避免误伤正常字符串；可用环境变量 `DRG_FIX_MOJIBAKE=0` 关闭。

> **pandas 3.x 兼容注意**：pandas 3 起字符串列默认 dtype 为 `str` 而非 `object`，
> 因此判断文本列不能用 `dtype == object`，须改用「非数值/非时间/非布尔」。此坑曾导致乱码修复静默失效。

**常用函数**：`connect()`、`query_df()`、`query_rows()`、`scalar()`、`server_info()`、
`table_exists()`、`list_tables()`、`row_counts()`、`fix_mojibake()`、`backend_of()`、`close_all()`。

> `row_counts()` 用 `sys.partitions` 统计行数，避免千万级表全表扫描。

## 五、`etl/excel_probe.py` —— Excel 结构探测 CLI

**职责**：为结算返回清单的 schema 自适应提供前置分析。

**背景**：医保每月返回的结算明细 Excel「格式逐月有差异」，不能对列序/列名做硬编码。工具用于：
1. 列出工作簿内全部 sheet 及其规模；
2. 自动识别真实表头行（前若干行里能匹配到已知业务关键词最多、且非空单元格最多的那一行）；
3. 输出列名清单与样例值，供人工确认后写入 `config/settlement_schema.json` 映射表。

**常量**：`HEADER_SCAN_ROWS = 12`（表头候选人扫描行数）、`SHEET_PREVIEW_ROWS = 3`（每列样例值行数）。

### 6.1 S00 环境体检

验证只读直连、驱动后端、SQL Server 版本，核对一期依赖的 12 个关键源对象是否在位及行数量级，
并检查本机结算返回样本是否齐备。报告作为一期开工留痕。

### 6.2 S01 结算返回导入（schema 自适应）

**输入**：`原始资料/DRG结算样表/*.xlsx`（逐月格式有差异，实测三套 schema）。
**输出**：统一规范表（一行 = 一次结算）。

**设计要点**：
1. **不硬编码列序**：按 `config/settlement_schema.json` 的 `candidates` 做列名匹配（精确 → 去空白 → 包含）；
2. **不硬编码表头行**：自动扫描前若干行识别表头（`guess_header_row`）；
3. **值级标准化**：退费标志（否/是 ↔ 0/1）、结付率（`'100.00%'` ↔ 100.0）、时间列 UTC +8h 还原；
4. 保留 `source_file` / `source_sheet` 溯源列，逐月差异可追溯。

**时间列还原规则（重要）**：3 月表时间串形如 `2026-02-20T16:00:00.000+`，是本地零点被按 UTC 序列化后的结果。
若直接解释会整体前移 8 小时（入院日期错到前一天）。规则：以 `+` 结尾者按 UTC 解析后 **+8 小时**还原。
校验方式：`(出院−入院) 天数 == 「住院天数」列`，实测一致率 99.5%。

### 6.3 S02 差异分析打样

**用途**：官方结算返回 × 院内预分组逐例对表，量化组码分歧率，是自建引擎转正前的**基线量化**。

**阶段**：
1. **主键核验**（`probe_keys`）：穷举候选关联键并给出命中率；
2. **抽取**：`源表(admission)` LEFT JOIN `源表(vendor_pre_grouping)`（同一病案多次预分组取最近一次）；
3. **对表**：组码一致率、ADRG 一致率、分歧分类、参数体检、诊断口径比对、预分组时效性、中医组识别率。

**关键判读**：`ADRG 一致而四位码不同` 说明主诊断/主操作已正确归入同一 ADRG，差异集中第 4 位；
`ADRG 不一致` 才是真正的分组逻辑分歧。只看四位码一致率会得出「整组重写」的错误结论。

`--probe` 仅做主键核验；`--key` 可切换用于匹配 HIS 住院号的官方列。

### 6.4 S03 官方分组目录提取

把《某地区按病组（DRG）付费 2.0 版细分组目录》docx 转为结构化 CSV。产出含：

### 6.5 S04 中医优势病组规则提取与核对

**为什么必须先核对**：27 号文规定中医优势病组按「对应西医主要诊断 + 中医主要手术或操作 + 住院时长」入组，
入组与否直接决定按中医组权重（IU2F 0.9258）还是普通内科组权重（IU23 0.6524）结算。
手上的 `原始资料/中医入组标准(1).xlsx` 是**手工转录件**，未经核对不得入引擎。

**官方两套入组条件（实测）**：
- **中医正骨术组**（IR1Z/IR2Z/IS1Z/IS2R/IS2Z/IU2Z）：「同时包含主要诊断和中医主要手术或操作，住院天数≥N」
  —— 诊断清单 × 操作清单**取交集**，任一操作即可；
- **中医治疗组**（IS2F/IU1F/IU2F/IZ2F）：官方列出「入组条件 1..5」，为「中医手术或操作 1/2/3/4」四类的组合，
  实测恰为 4 类中任取 3 类（C(4,3)=4 组）加全取 1 组 → **等价于至少覆盖 3 类**。

**解析器必须容错的官方写法**（原文自身不一致）：
- 细目分隔符大小写混用：`M17.900x003` 与 `M22.200X001`；
- 操作类表头三种写法：`中医主要手术或操作` / `中医手术或操作 1：`（带冒号）/ `中医治疗性操作表 2` / `中医中医手术或操作 4`（原文重复「中医」）；
- 入组条件常被 PDF 换行拆断（`中医手术或操作\n1+中医手术或操作2`），**必须先拼回整块再解析**，否则类号会漏。

**附件定位陷阱**：正文中有「（见附件2）」这类引用，直接 `find('附件2')` 会命中引用而非附件本体，
必须用附件标题一起定位（正则 `附件\s*N\s*<标题前缀>`）。

### 6.6 S05 规则回测验证

用 S04 从官方 PDF 提取的规则对 N 例做**独立重算**，与官方结算结果逐例比对。

**前置：新旧手术编码映射**。`源表(operation).列(code)` 是国临/院内码（如 `99.9201 毫针刺法`），
27 号文用医保版码（如 `17.91100 毫针治疗`），经 `原始资料/数据字典/本地对照表.csv`
（`列(kind)='S'`，13,734 条）可完全映射，窗口内 56 个院内码 100% 命中。

**编码归一化**：官方 PDF 与院内数据的细目分隔符大小写不一致（X/x），比对前必须统一大写，
否则会出现「规则明明有、就是匹配不上」的假性不匹配。

### 6.7 S06 在院 DRG 模拟器 v0

**产品定位**：本单位 97% 以上为内科组、IU2F 占收入 40~50%，盈亏命门是中医优势病组能否入组。
住院医师需要在**住院期间**知道：我的患者现在会入哪个组、还差什么条件、费用是否已超支付标准。
本工具不嵌 HIS（既有系统已退出），以「内网脚本 + 每日清单」形态交付。

**四行输出**：① 当前预分组 ② 入组差距 ③ 费用预判 ④ 优化空间（仅白名单内）。

**实现要点**：
- 在院口径：`列(mark_out) = 0 AND 列(time_out) IS NULL`；
- 在院主诊断：`列(kind_input) IN (1,2)`（入院/修正）+ `列(kind_diagnose) = 2`（西医）+ `列(order) = 1`；
- ②行**只对「主要诊断已命中该组清单」的病组提示差距**，否则会输出大量无关病组，对临床是噪声；
- 差距仅为住院天数时，④行显式声明「按临床规范执行，不做人为干预」（合规护栏）。

**合规护栏**：
- 白名单（允许输出）：主要诊断/主要操作的正确选择与顺序、漏编中医操作与 CC/MCC 的补录提醒、中医病证规范填报；
- 黑名单（永不生成）：建议增加诊疗项目、建议延长住院、建议改诊断以入更高权重组；
- 全部输出标注「基于当前已录入信息推演，分组结果以医保平台为准」。

**参数口径**：费率 `9,575.25`、机构系数 `0.92`、权重取官方 839 组目录**二三级医疗机构权重**列。

### 6.8 S07 财务对账包 v1

**勾稽设计**：① HIS 费用三表按住院号汇总（可下钻统计码科目）② 官方结算返回的总费用 / 支付标准 / 盈亏额及基金自付拆分
③ 差异分类与追查单。

**两项口径定版（本作业的核心结论）**：
1. **对账口径 = 费用明细中 `列(money) > 0` 的合计**。实测：净额口径逐例一致率仅 24.5%，
   剔除退费/红冲负数行后跃升至 **99.5%**（含负数行的病例占 75.5%）。差异根因是**口径定义**而非数据缺失；
2. **官方盈亏额 = DRG 支付标准 − 住院医疗总费用**（正数 = 医院盈利）。正向公式一致率 97.00%、反向 0.00%；
   残差主要为官方置 0 的**高低倍率病例**（某地区医保局〔2025〕26 号：费用极高前 5%、极低 <40% 按项目付费）。

**基金/自付拆分来源（推翻 docs/05 判断）**：`源表(settle_bill)` 的四个金额列
（甲类/乙类/自付/其他）近一年半 401,265 行**填充率均为 0%**；`源表(invoice_title).列(hospital_no)` 填充率仅 4.7%
（主要为门诊发票）→ **改以结算返回自带拆分字段为准**。

**单例追查**：`--diag <住院号>` 输出该例在三张费用表中的科目级构成，供财务逐笔核对。

**中治率可行性**：统计码 `10/12` 为**混合「治疗费」**，无法区分中医/西医；卫生材料费无对应统计码
→ 需先建立「收费项目 → 中医/西医治疗费 + 卫生材料费」科目映射，否则中治率只能给上界估计。

### 6.9 S08 盈亏基线看板

**口径**：月度盈亏 = Σ 官方「盈亏额」；CMI = 例数加权平均权重；中医优势病组占比 = F/R/Z 结尾组例数占比。

**三层**：全院（月度）→ 病组（Top/Bottom，含例均费用与例均盈亏）→ 科室。

**科室映射**：官方返回 4/5 月表的「科室名称」列为空，科室取 **HIS `列(office_now)`** 经
`Clinical_Office` 字典（`列(code_his)` 形如 `1045|预防保健科`）映射；3 月表官方科室名可用于抽样校验。

**注意事项**：2026 年 3 月返回表（52 列 schema）**不含「盈亏额」列**，看板中 3 月盈亏显示 0
是数据缺失而非真实为 0，报告已显式标注。

## 七、跨模块的领域约定（写在这里，不写在代码里）

| 约定 | 内容 |
|---|---|
| 业务主键 | 官方「病案号」= HIS `源表(admission).列(hospital_no)`，实测命中率 100% |
| 住院医师口径 | `源表(admission).列(doctor_residency)`，实际格式为 **`工号\|姓名`**（如 `51015\|示例医师甲`），存在空值 |
| 诊断口径 | `列(kind_input)` 1=入院/2=修正/3=出院/4=终版（取 3 或 4）；`列(kind_diagnose)` 1=中医病/2=西医/3=证型；`列(order)=1` 为主诊断 |
| 在院操作口径 | `源表(operation)` 是**病案环节**表，住院期间基本为空（实测在院 120 例中仅 5 例有记录） |
| 费用取数 | `源表(fee_check_in)` / `_Cure_In` / `_Medicine_In`，过滤 `列(mark_dell) = 0` |
| 源库中文乱码 | varchar 中文列可能按 latin-1 解码，由 `dbio.fix_mojibake()` 统一还原 |
| 政策版本留痕 | 规则表每行带 `policy_version`（当前 `某地区医保局〔2025〕27号-2025版`） |
