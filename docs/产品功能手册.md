## §1 分组引擎（drg_engine / s11）

- **① 功能概述**：确定性 DRG 预分组引擎，双路径——先判中医优势病组（27 号文属地叠加），未命中走标准 CHS-DRG 2.0。输出组码/权重/支付标准 + 分组证据链（policy_version）。[来源: 19][来源: 18]
- **② 输入/输出**：输入 = 主诊断 + 主操作 + 其他诊断 + 住院天数（**不含用药**，见需求 §3.1/29-分组器业务逻辑）；输出 = ADRG/四位码/权重/支付标准/分组依据 reason。
- **③ 核心脚本/文件**：`src/etl/drg_engine.py`（运行时引擎，双路径 `TcmGrouper`+`StandardGrouper`）、`src/etl/s11_adrg.py`（字典抽取与回测，唯一回测入口 `run_backtest()`）、`src/etl/s03_extract_group_catalog.py`；字典 `src/config/dict/drg_group_catalog.csv`（839 组）、`drg_qy_groups.csv`（20 QY 伪组）、`drg_{cond,drg,adrg,main_dx,cc,mcc,exclude,no_main_dx,no_main_op}.csv`（9 张 CHS-DRG 字典）。
- **④ 关联需求**：FR-3.1.1~3.1.5、NF-4（部署回滚）。
- **⑤ 成熟度**：**②已建成待验证**（回测 PASS：ADRG 96.9% / 四位码 88.1%（run #11），超越既有系统 90.9%/17.4%；影子运行收口中）。
- **⑥ 已知缺口**：MDCZ 多发严重创伤跨 MDC 规则已存 `dict_mdcz_dx`（997 条）但未接入引擎，需 ISS 严重度条件（P1，评估 A1）；国家表×某地区目录严重程度回退链已修但须保留留痕。

## §2 中医优势病组（s04 / s05 / s34）

- **① 功能概述**：识别 27 号文附件2 的 10 个中医 DRG 病组（IU2F 等），含中治率≥60% 前置校验与中医特色病种倾斜测算。是本单位盈亏命门（占约 70% 结算病例、IU2F 占收入 40~50%）。[来源: 12][来源: 16]
- **② 输入/输出**：输入 = 主诊断 + 中医操作类覆盖 + 住院天数（及费用科目映射算中治率）；输出 = 是否入中医组 + 组码/权重/支付标准 + 中治率判定。
- **③ 核心脚本/文件**：`src/etl/s04_extract_tcm_rules.py`（规则提取+与官方 PDF 逐条核对）、`src/etl/s05_validate_tcm_rules.py`（回测）、`src/etl/s34_tcm_calibrate.py`（触发校准）、`src/etl/tcm_ratio.py`（中治率/操作类共用模块）；字典 `src/config/dict/tcm_advantage_rules.json`（379 条，含 policy_version）、`src/config/dict/cost_item_attribute.csv`（12,546 条，is_tcm_item/zzl_subject/op_class）、`src/out/tcm/tcm_predictions.csv`。
- **④ 关联需求**：FR-3.2.1~3.2.4、M8（中治率口径）。
- **⑤ 成熟度**：**①已建成生产可用**（回测召回/精确 99.8%；中治率与官方一致 99.5%/100%）。
- **⑥ 已知缺口**：`s34` 校准发现 76 例「引擎入中医组/平台入标准组」，待使用方确认口径后收紧触发门限（P3，评估 A2）；中医特色病种倾斜比例测算待二期接入盈亏。

## §3 在院模拟器（s06 / daily_insim）

- **① 功能概述**：使用方一号需求。住院医师（经管医师）视图「我的在院患者」，固定四行输出：①当前预分组 ②入组差距 ③费用预判 ④优化空间（仅白名单内）；每日按医师自动推送清单。不嵌 HIS（内网网页形态）。[来源: 13][来源: 19][来源: 10]
- **② 输入/输出**：输入 = 在院病例（`列(mark_out)=0`）+ 在院主诊断（kind_input 1/2）+ 已执行操作（医嘱 `列(time_execute) IS NOT NULL`）+ 费用三表 + 中医规则/目录；输出 = 四行 + 中治率列 + 每日清单（`out/insim/insim_<日期>.csv`）。
- **③ 核心脚本/文件**：`src/etl/s06_insim.py`（v1，接 drg_engine）、`src/run/daily_insim.py`（SCHTASKS 每日 08:00 调 s06 → s18 --load，落 `result_insim`）；合规措辞在 `s06._advice()/_gap_text()`，受 W01/W02/W03/W04/W17/W18 闸门。
- **④ 关联需求**：FR-3.3.1~3.3.4、关联 W04/W17 非干预措辞（需求 §3.9）。
- **⑤ 成熟度**：**②已建成待验证**（120 例实测：中医组 25 / 标准组 53 / 未产出 42；医嘱数据源已接 5→94/120）。
- **⑥ 已知缺口**：① 35%（42/120）在院患者无西医主诊断，①行覆盖率受限（P1，评估 A3）；② 每日清单推送渠道未接（仅 web/控制台，P1）；③ 标准路径在院早期无手术码时推演须带「暂按主诊断判内科组」限定。

## §4 财务对账（s07 / s10）

- **① 功能概述**：月度对账包，按住院号**明细到笔**三方勾稽：HIS 费用明细 ↔ 结算返回 ↔ 医保基金/自付拆分；差异分类 + 单例追查单。[来源: 14][来源: 17]
- **② 输入/输出**：输入 = 费用三表（Check/Cure/Medicine_In，过滤 `列(mark_dell)=0`）+ 结算返回 + 医保交互表；输出 = `out/recon/recon_cases.csv` + 对账报告 + 单例 `--diag <住院号>` 科目级构成。
- **③ 核心脚本/文件**：`src/etl/s07_reconcile.py`（正数口径 + 负数列 + 第六章中治率逐例校验）、`src/etl/s10_settle_link.py`（结算ID↔住院号关联，100% 命中 `源表(settle).列(bill_no)`）。
- **④ 关联需求**：FR-3.4.1~3.4.3、M7（对账口径）。
- **⑤ 成熟度**：**①已建成生产可用**（正数口径逐例一致率 99.5%；官方盈亏额公式复现 97.0%）。
- **⑥ 已知缺口**：`源表(settle_bill)` 与住院号关联未打通（科目级三方校验待补，P2）；对账口径 W10 待财务科最终签认；3 月返回缺盈亏额字段（已公式补算并标注）。
