# docs/32 · 四位码一致率根因与反事实验证

> **作业**：`src/etl/s33_dx_counterfactual.py`（`--part a` 反事实 / `--part b` 根因分解，只读）
> **数据**：`drg.dbo.result_compare_case` 全量 **N 例**（引擎预测 vs 医保平台实际回执）
> **关联**：`docs/31` §1.10（S32 线索来源）、`docs/23`（引擎指标）、`docs/19`（引擎接入）

## 0. 一句话结论

**补录 S32 找出的「漏编其他诊断」对入组结果零影响（56 例全部无变化）。**

**真正的首要根因已定位并修复：住院天数取自结算返回，而该列约 78% 为空 → NaN 参与 `days < 门槛`
比较恒为 False → 中医优势病组的住院天数门槛被整体绕过。改用 `源表(admission).列(inhospital_day)` 后，
四位码一致率 80.4% → **86.5%**（+52 例），误入中医组 89 → 29。**

> 修复后剩余差距的主因转为 **CC/MCC 少判「伴合并症」（第 4 位 5 → 官方 3，58 例）**，即下阶段的 P1。

## 1. 反事实验证（补入候选其他诊断会怎样？）

| 项 | 结果 |
|---|---|
| S32 线索病例中落在对照表内的 | **56 例** |
| 基线复现校验（自算 vs 表内 `grp_engine`） | **51/56**（91%，入参装配可信） |
| 补入候选诊断后**分组发生变化** | **0 例** |
| 四位码一致数 | 基线 **33** → 补入后 **33** |
| 变好 / 变坏 | **0 / 0** |

> 结论：这些"疑似漏编"**不影响 DRG 入组与结算金额**。

### 1.1 为什么零变化（两个机制原因，均已实测证实）

| 原因 | 证据 |
|---|---|
| **中医组路径不读其他诊断** | `DrgEngine.group()` 先调 `TcmGrouper`，命中即返回；`other_dx` 只在标准路径参与定档位。56 例中 **36 例（64%）走 tcm 路径** |
| **候选码大多在 CC/MCC 排除表内** | 10 个高频候选中仅 `M81.900`(骨质疏松)、`S52.802`(尺骨茎突骨折) 为 **CC**；`I10.x00x002`(高血压)、`E14.900x001`(糖尿病)、`I25.103`(冠心病)、`E79.001`、`K29.500`、`I45.102`、`G95.800x010`、`M17.900x003` 全部为 **EXCLUDE**（CHS-DRG 排除表，不计入 CC/MCC） |

> 即：即便补录，也被排除表挡掉；且多数病例本就走中医组，补什么码都不改结果。

## 3. P0 已执行：住院天数源修复（已完成并验证）

### 3.1 根因

| 项 | 事实 |
|---|---|
| 现象 | 引擎把 89 例判入中医优势病组，官方判入标准组 |
| 直接原因 | 中医组规则含住院天数门槛（10/12/20 天），但门槛实际**未生效** |
| 底层缺陷 | `days` 取自结算返回 `actual_days`，**673/N 例（78.3%）为空**；`NaN < 门槛` 恒为 False → 门槛被绕过（与 `docs/21` 同类缺陷） |
| 佐证 | `源表(admission).列(inhospital_day)` **N/N 有值**，且与官方 `actual_days` **12/12 抽样完全一致** |

> 旁证：s05 / s09 / s14 早已使用 `列(inhospital_day)`（s14 有专门注释），**仅 s11 仍在用结算返回天数**，属取数不一致。

### 3.2 修复

`src/etl/s11_adrg.py`：天数源改为 `源表(admission).列(inhospital_day)`，缺失时回退 `actual_days`。

### 3.3 验证（`python src/etl/s11_adrg.py` 重跑，N 例）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| **四位码一致** | 691（80.4%） | **743（86.5%）** |
| ADRG 一致 | 823（95.8%） | 823（95.8%） |
| 误入中医组 | 89 | **29** |
| ADRG 同但档位异 | 132 | **80** |

### 3.4 被否证的两个假设（留档，避免重复试错）

| 假设 | 结论 |
|---|---|
| 收紧「操作类覆盖 ≥3」 | 仅 +3 例；且现有规则已按 27 号文设 `min_ops=3`，全局再收紧会**误伤合法正骨术病例**，不采纳 |
| 加「中治率 ≥60%」门槛 | 无增益（最优组合中该维度为 0），不采纳 |
| 收紧住院天数门槛（全局 ≥5/8/10…） | 天数修复前是灾难（78% 病例直接失败）；修复后全局门槛**无额外增益**（各组既定阈值已足够），不采纳 |

### 3.5 修复后剩余缺口构成

| 分层 | 例数 |
|---|---|
| ADRG 相同但档位不同 | **80** |
| ADRG 不同 | 36 |

档位差异方向（引擎 → 官方）：**5→3（58 例，主导）**、Z→5（11）、3→5（9）、Z→3（7）、9→3（3）。

> 即：**引擎少判「伴合并症或并发症」**是修复后的首要差距 → 下阶段 P1。

## 4. P1 已执行：CC/MCC 排除表口径修正（根因已定位，净增益有限）

### 4.1 根因（实测）

`S35` 对「引擎判不伴(5)、官方判伴合并症(3)」的 **53 例**逐例归因：

| 归类 | 例数 |
|---|---|
| **被排除表挡掉** | **53（100%）** |
| 未录入 / CC 表未收录 / 平台比 HIS 多码 | 0 |

进一步量化：这 53 例的其他诊断中属 CC/MCC 的编码共 **86 个**，其中 **86 个（100%）被排除表挡掉，无一计入**。
（例：M81.900 骨质疏松、I48.900X004 房颤、S32.100、M35.000、G62.901）

### 4.2 真正的机制错误

| 项 | 说明 |
|---|---|
| 官方结构 | `CC`/`MCC` 表**每一行携带「排除内容 = 表 6-3-N」**；该表列出的是**与该 CC 同源/相关的诊断**（如 M81.900 骨质疏松 → 表 6-3-134 → M80.x 骨质疏松伴病理性骨折） |
| 原实现 | `cands = other_dx - exclude`，把 **211 张表共 24,309 个码并成一个全局黑名单**，凡出现在任何一张排除表的其他诊断一律剔除 |
| 后果 | 几乎所有合并症都被剔除 → 系统性少判「伴合并症」 |

### 4.3 修复

`drg_engine.py`：改为**按 CC 码各自绑定的排除表**判定——某合并症仅当**主诊断命中它自己的排除表**时才不计入。

### 4.4 效果（诚实记录）

| 口径 | 四位码一致 |
|---|---|
| 天数修复后、排除表未修 | **743**（86.5%） |
| ＋排除表修正（S11 权威口径） | **743**（86.5%） |
| ＋排除表修正（S34 回放口径） | **748**（87.1%） |

> **净增益：0（S11）/ +5（回放）**。两者差异来自主诊断兜底来源不同
> （S11 回退 `源表(vendor_pre_grouping)`，回放回退对照表字段）。
>
> 排除表口径已不再是主要瓶颈——修正后「5→3」型误判由 53 例降至 **0**，
> 但出现约 47 例「3→5」型（引擎多判合并症），正负相抵。

### 4.5 剩余的真正瓶颈

1. **主诊断来源不一致**：HIS 终版主诊断缺失时回退既有预分组码，该回退码可能触发排除表。
2. **HIS 其他诊断 ≠ 平台收到的其他诊断**：实测同一病例 HIS 记 5~12 条，平台回传仅 3~6 条
   （`S35` 明细），我们按 HIS 全量判定，必然比平台多算合并症。
   → 与 `docs/22` 的 P0（索取结算清单上传件）是同一件事，**这才是闭环的关键**。

## 4. 对使用方的直接意义（重要）

1. **"补录其他诊断"不是收益问题** —— 反事实验证 0 例变化，补录不会改变入组与结算金额。
   它仍是**病案质量与合规**问题（按真实、准确、完整原则填报），但不该被当作提升收入的手段。
2. **真正的收益杠杆在引擎判定本身**（中医组触发条件、CC 判定），不在补录。
3. 此结论同时印证 `docs/22` 的判断：不要以"入组/权重"为导向增删诊断
   （黑名单 B01–B09）；本次数据给出了量化证据——**改判定比改编码有效得多**。
